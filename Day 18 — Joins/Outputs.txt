[info] 21. JOIN TYPES SUMMARY
[info] ================================================================================
[info] INNER JOIN
[info] -----------
[info] Returns only matching rows.
[info] LEFT JOIN
[info] ---------
[info] All rows from left table.
[info] Unmatched right columns become NULL.
[info] RIGHT JOIN
[info] ----------
[info] All rows from right table.
[info] Unmatched left columns become NULL.
[info] FULL OUTER JOIN
[info] ---------------
[info] All rows from both tables.
[info] Missing side becomes NULL.

[info] 22. DAY 18 VIVA SUMMARY
[info] ================================================================================
[info] Q1. What is a join?
[info] A:
[info] A join combines rows from two datasets based on
[info] a related column or condition.
[info] Q2. What is an inner join?
[info] A:
[info] It returns only rows having matching keys in both datasets.
[info] Q3. What is a left join?
[info] A:
[info] It keeps every row from the left dataset.
[info] If there is no match on the right side, right-side
[info] columns become NULL.
[info] Q4. What is a right join?
[info] A:
[info] It keeps every row from the right dataset.
[info] Q5. What is a full outer join?
[info] A:
[info] It keeps rows from both datasets, including unmatched rows.
[info] Q6. Why do we use aliases?
[info] A:
[info] Aliases distinguish columns from different DataFrames
[info] when they have the same column name.
[info] Example:
[info] orders.alias("o")
[info] customers.alias("c")
[info] col("o.customer_id")
[info] col("c.customer_id")
[info] Q7. How do you handle NULL after a left join?
[info] A:
[info] Use functions such as:
[info] coalesce()
[info] when()
[info] isNull()
[info] na.fill()
[info] Q8. What is Shuffle Sort Merge Join?
[info] A:
[info] It is a Spark join strategy where both datasets are
[info] partitioned/shuffled according to the join key,
[info] sorted within partitions, and then matching rows
[info] are merged.
[info] Q9. Why does shuffle happen during a join?
[info] A:
[info] Rows having the same join key may initially exist
[info] in different partitions. Spark redistributes them
[info] so matching keys can be brought together.
[info] Q10. Why is shuffle expensive?
[info] A:
[info] It can involve network transfer, disk I/O and sorting,
[info] which adds execution overhead.
[info] Q11. What is a broadcast join?
[info] A:
[info] Spark can broadcast a small dataset to executors so
[info] the larger dataset does not need a full shuffle for
[info] that join.
[info] Q12. When might Spark use a broadcast join?
[info] A:
[info] When one side of the join is sufficiently small and
[info] Spark's optimizer determines that broadcasting it is
[info] appropriate.
